# 작업공간 상호작용 구현 계획

2026-10-21 · 상태: P0·P1 로컬 구현·PostgreSQL/웹/브라우저 검증, 운영 미배포 · 근거: [REA/브라우저 재분석](../planning/13-task-interaction-rea.md) · APP-REQ-021~027 / AC-40~51

기존 [작업공간 구현](task-workspace.md)은 목록·보드·캘린더·집계의 첫 표시와 상태 선택을 제공한다. 이 계획은 화면에서 직접 일을 움직이는 다음 단계다. 코드 변경과 배포의 완료는 이 문서로 판정하지 않는다.

## P0 구현 결과와 남는 확인

- PostgreSQL `task_positions`와 `0004_task_positions` migration이 작업별 수동 순서를 보존한다. 기존 작업은 생성 시각·ID 순서로 결정적으로 표시되고 첫 이동 때 위치 레코드를 만든다. 프로젝트 행 잠금, 작업 revision, 원본 상태, 이웃의 열을 서버에서 재검사한 뒤 상태와 모든 영향 순서를 하나의 트랜잭션으로 갱신한다. 일반 작업 수정과 같은 완료 gate를 호출한다. 프로젝트 ZIP도 순서를 보존하며 과거 ZIP의 누락 필드는 허용한다.
- `POST /api/items/{id}/move`를 보드 드래그, 화살표, 상태 팝오버, 작업 메뉴가 공유한다. 응답의 원래 위치 anchor와 새 revision으로 직전 이동을 다시 같은 API에서 되돌린다. 필터에 숨은 작업은 서버 순서에 남긴다. UI는 보이는 이웃 한 개만 anchor로 보내며 GTD/ABC 자동 보기는 상태 변경 시 대상 수동 순서의 끝에 붙인다. 자동 보기에서 열 안 순서 변경은 막는다. 보드 정렬 선택과 한 번의 되돌리기는 프로젝트별 브라우저 세션에 유지한다.
- 고정된 `ui.pydemia.ai` Kanban·Popover·DropdownMenu source를 편입했다. 카드 핸들만 드래그하고 빈 열·카드 위/아래의 drop target, 가로/세로 자동 스크롤, Escape 메뉴 닫기, 상태 검색, 키보드 화살표 버튼을 제공한다. 실패 시 낙관적 화면을 복원하고 최신 목록을 다시 요청해 재시도를 안내한다. 포인터 드래그·새로고침 지속성·상태/작업 메뉴는 격리된 로컬 브라우저에서 확인했다.
- 약 464 CSS px 좁은 폭에서 가로 보드 스크롤·검색 팝오버 선택과 다섯 카드가 있는 긴 열의 자체 세로 스크롤을 브라우저에서 확인했다. 드래그 중 긴 열 자동 스크롤과 무효 드롭은 DOM 이벤트 검사로 확인했다. 수동 스크린리더 감사, 실제 터치 기기, 자동 스크롤의 실제 포인터 검사는 남아 있다. 운영 배포와 Entra 로그인도 이번 P0의 로컬 검증과 별도다.

## 1. P0: 단일 카드의 이동과 수동 순서

1. `TaskData.state`, `abc_order`, GTD 필드와 별개의 작업 수동 순서를 PostgreSQL에 둔다. 프로젝트·상태별 순서와 이웃 ID를 안정적으로 조회하고, 기존 작업은 결정적인 순서로 이관한다. `items.data`의 상태와 순서 레코드를 같은 트랜잭션에서 갱신한다. rank 자료형·재균형 방식은 동시성/대량 데이터 테스트 후 확정한다.
2. 프로젝트 범위의 `move/reorder` 명령은 작업 ID, 기대 revision, 원본·대상 상태, 앞/뒤 이웃 ID를 받는다. 서버가 실제 현재 상태·이웃·권한을 재검사해 위치를 계산한다. 일반 `saveItem`과 같은 완료 gate를 호출하고, 구현 작업의 근거 없는 완료를 우회하지 않는다. 성공 응답은 새 revision·상태·순서를 돌려준다. 다른 세션 변경은 409, 무효 위치는 422, 권한 없음은 403으로 구분한다.
3. 보드 기본 정렬을 수동으로 두고 카드 핸들, 컬럼 드롭 영역, 위치 표시, 자동 스크롤, 드래그 취소, 진행/오류/되돌리기 UI를 만든다. 카드 본문은 상세 열기, 필드 버튼은 편집으로 유지한다. 키보드·터치에는 상태 선택과 위/아래 이동 메뉴를 제공한다. 자동 GTD/ABC 정렬 중에는 수동 재정렬을 막고 이유를 보여 주되 상태 이동은 가능하게 한다.
4. 상태 배지는 현재 값·후보 그룹·검색을 가진 상태 팝오버를 열고, `…`는 Projects에서 구현한 작업 행동만 모은 메뉴를 연다. 메뉴의 상태/순서 이동은 드롭과 동일한 `move/reorder` 명령을 호출한다. 다른 목록으로 옮기기는 독립된 명령과 대상 표시를 사용한다. 간편 모드는 완료·오늘·이동·편집을 우선, 정교 모드는 필드 바로 편집을 허용한다. 팝오버는 화면 경계에 맞게 배치하고 Escape·바깥 클릭·선택 후 닫기와 카드로의 초점 복귀를 검증한다. 드래그 시작이 메뉴 버튼 클릭으로 오인되지 않도록 이벤트 경계를 둔다.
5. `ui.pydemia.ai` registry에 정렬/드래그·Popover·Menu primitive와 피드백 상태가 있는지 확인하고 source revision/hash를 기록한다. 없다면 공통 UI 계층의 접근 가능한 상호작용 계약을 먼저 정의한다. 기존 Card·Badge·Dialog·Tabs·토큰과 연결하며 Projects 전용 시각 복제품을 만들지 않는다.
6. 실패한 낙관적 이동은 기존 순서/카운트를 복원한다. 성공 직후 되돌리기는 다시 서버 revision을 확인해 실행한다. 필터로 숨은 작업을 이웃 계산에서 제거하지 않는다. 실제 전체 순서는 서버가 결정한다.

**완료 증거:** `AC-40~45·AC-50~51`의 PostgreSQL 통합 검사와 실제 포인터/키보드/모바일 폭 브라우저 검사. 상태 메뉴·작업 메뉴·드롭으로 같은 이동을 각각 수행해 결과·완료 gate·실패 복구가 일치하는지 확인한다. `npm --prefix web run check`, `npm --prefix web run build`, 저장소 `AGENTS.md`의 서버 검사 명령을 통과한다. 테스트 하나는 다른 세션이 같은 작업을 바꾸는 409와 화면 복구를 포함한다.

## 2. P1: 생성·일괄 처리·오늘 계획·저장된 보기

- 상태 열의 `+ 작업`은 열 상태와 끝 위치를 상속한다. 제목만으로 생성하고 추가 필드는 펼침/상세에서 편집한다. 신규/기존 작업의 동일 ID를 목록·보드·캘린더·집계가 읽는다.
- Shift/체크박스 다중 선택과 선택 수를 보여 주는 도구막대를 추가한다. 일괄 상태·실행 예정일·목록 이동은 서버에서 전체 권한/완료 조건/기대 revision을 검사한 후 원자적으로 적용한다. UI는 혼합 결과를 성공으로 오인하지 않는다.
- 간편 보기의 Inbox→오늘 계획→완료/연기 흐름을 단축한다. 오늘 배치는 `planned_date`의 의미만 바꾸고 `due_date`는 보존한다. 자동 밤 초기화나 반복/알림을 이 단계에 섞지 않는다.
- 보기 설정은 작업 데이터와 분리한다. 개인/공유 범위, 기본 보기, 필터·그룹·정렬·카드 필드를 명시해 저장한다. 여러 사람에게 영향을 주는 보기 설정은 권한과 저장 여부를 보여 준다. 개인 칸반 섹션은 `state`와 별도 데이터 구조의 필요성을 검증한 뒤 설계한다.

**완료 증거:** `AC-46~48`의 생성 상속, 다중 전체 성공/전체 거부, 날짜 불변 및 보기 소유권 검증. ClickUp 등 외부 제품의 동작을 Projects의 테스트 결과로 대체하지 않는다.

### P1 로컬 구현 결과 · 2026-10-21~22

- PostgreSQL `0005_task_views`는 보기 설정을 작업 데이터와 별도 행에 보관한다. 프로젝트 소유자 개인 보기만 API·화면에서 허용한다. 현재 프로젝트 권한은 단일 소유자이므로 `shared` 범위는 422로 거부하며 팀 권한 계약을 만든 것처럼 표시하지 않는다. 개인 기본 보기는 한 개로 제한하고, 프로젝트 ZIP 반출·복구 시 소유자를 복구 계정에 다시 연결한다.
- 상태 열의 빠른 생성은 개인 작업으로 상태와 끝 수동 순서를 상속한다. 취소 열은 사유를 요구한다. 다중 선택은 체크박스·Shift 범위·현재 보기 전체 선택을 제공한다. 일괄 상태·실행 예정일·목록 변경은 한 프로젝트 잠금과 모든 기대 revision·완료 조건의 사전 검사 후 단일 트랜잭션에서 revision과 보드 순서를 갱신한다. 실패하면 전체를 거부하고 선택·오류를 유지한다.
- 간편 보기에서는 Inbox 작업을 오늘로 배치하고 오늘 작업을 내일로 연기한다. 이 경로는 `planned_date`만 변경하며 `due_date`는 보존한다. 지난 마감일 때문에 오늘에 남는 작업은 이유를 표시한다. 저장된 보기는 검색·상태·GTD 조건·그룹·정렬·카드 필드와 기본 보기 여부를 명시적으로 저장한다. 간편 목록은 그룹을 숨기고 GTD/ABC 정렬을 사용하며, 정교 목록 그룹은 상태/목록을 지원하고 보드 그룹은 상태 열로 고정한다. 그룹·정렬·카드 필드의 효과가 없는 캘린더·집계에는 해당 컨트롤을 노출하지 않는다.
- 로컬 격리 PostgreSQL과 실제 브라우저에서 열별 생성, Inbox→오늘→연기, 다중 상태 변경·새로고침, 기본 보기 재방문, 근거 없는 구현 작업과 개인 작업을 함께 완료하려는 시도의 전체 거부·오류/선택 복구, 그룹 내 Shift 범위를 확인했다. 실제 운영 배포·Entra 로그인 및 팀 공유 권한은 이번 증거에 포함하지 않는다. 명령·개별 판정은 [검증 기록](verification.md)의 P1 절을 따른다.

## 3. P2: 달력 조작과 이력 기반 집계

- 날짜 없는 작업 트레이와 달력 드래그는 시간대·하루 경계·반복 항목·`planned_date`/`due_date` 계약을 먼저 확정한다. 일정 이동은 기본적으로 실행 예정일만 바꾼다.
- 작업의 상태/일정 변경 이벤트를 사용자·시각·전후 값과 연결해 저장한 후 처리량·체류시간 그래프를 만든다. 이력 도입 전 기간은 `자료 없음`이며 현재 스냅샷을 과거 추세로 간주하지 않는다.
- GitHub Issue 읽기/양방향 동기화는 별도 연동 작업이다. Projects 보드 조작은 현재 URL 연결의 외부 상태를 변경하지 않는다.
