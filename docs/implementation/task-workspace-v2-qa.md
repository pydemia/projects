## 권장 QA 흐름

개요에서는 프로젝트 01처럼 테스트 케이스가 없으면 ‘테스트 통과’ 지표를
숨기고, 프로젝트 02처럼 등록된 케이스가 있으면 기존 통과율을 표시한다.
간편/표준 프로필과 무관하다. 모바일에서 ‘현재 프로젝트 전체’ 다음 줄에
프로필/건수가 간격을 두고 표시되는지도 확인한다.

1. `전체 작업`에서 프로젝트가 다른 태스크를 검색하고 소속을 확인한다.
   프로젝트를 선택하지 않은 채 목록·보드·캘린더·집계가 모두 열리는지 확인한다.
2. 프로젝트 01의 오늘에서 `지난 계획`을 찾고 원래 날짜·그룹 중복 여부를 본다.
   같은 작업을 연 채 `보기 모드 · 간단/상세`와 목록/보드/캘린더/집계를 전환하고 초안·검색·선택,
   목록 GTD→보드 수동→목록 정렬 복원을 확인한다.
3. 달력의 날짜 없는 항목과 다음 달 항목, 저장 보기의 변경 중·명시 복원과
   빈 검색어, 새로고침·뒤로 가기를 확인한다.
4. 프로젝트 02의 `연결된 구현 작업`을 03으로 옮기고 ID·요구·기준선·이력을
   확인한 뒤 되돌린다. `일괄 이동 A/B`도 함께 이동·되돌리기한다.
5. `의존 작업`과 `테스트 gate`는 완료 근거가 없는 상태다. 완료 차단을
   확인한다. `충돌 확인`은 두 탭에서 먼저/나중에 저장해 초안 보존을 확인한다.
6. Note에는 실제 접근 가능한 문서 URL을 연결한다. 권한·본문은 미확인으로
   표시되어야 한다. 모바일의 긴 제목·완료·상세 복귀·이동 버튼도 확인한다.
7. 프로젝트 02를 선택한 뒤 다른 메뉴·프로젝트 목록·모바일 오늘/Inbox/작업,
   새로고침을 거쳐도 02가 유지되는지 확인한다. `전체 작업`으로 명시 이동한
   뒤 프로젝트 메뉴를 누르면 02로 돌아와야 한다.
8. 모바일 헤더의 목록/보드/캘린더/집계와 간단/상세를 직접 선택한다. 하단
   탐색이 계속 보이는지 확인한다. 보드에서 카드 위를 좌우로 밀어 열을
   탐색하고 상태 이름 버튼·메뉴 이동·undo·새로고침 후 최근 열 복원을 확인한다.
   열 탐색 스와이프만으로 카드 상태나 본문이 바뀌면 안 된다.
9. 개인 작업의 작은 체크와 주변 영역을 눌러 완료·다시 열기를 확인한다.
   상세→일괄 선택→간단으로 전환해도 완료 체크가 보여야 한다. 구현 작업은
   상태 드롭다운으로 바꾸고, 근거 없는 완료 차단·사유 없는 취소 차단과
   돌아가기 시 무변경을 확인한다.

## 추가 QA · 간단한 입력·필드·저장 보기

2026-11-02 새 기능도 운영 배포했다. 위 4개 프로젝트·24개 태스크는 그대로
보존했으며 운영에 사용자 필드나 가짜 실행 결과를 자동 추가하지 않았다.

1. 프로젝트 04에서 제목만 입력하고 Enter로 만든다. 날짜·필드 입력을
   강제하지 않고 바로 목록에 나타나야 한다. 모바일은 `+ 추가`의 한 줄 입력이다.
2. 데스크톱 `+ 필드`, 모바일 `필드`에서 표시/숨김·위/아래 순서를 바꾼다.
   ‘사용자 필드 추가’로 텍스트·숫자·날짜·선택·체크박스를 만든다. 정의는
   개인 작업공간에서 재사용되고 숨겨도 기존 값은 지워지지 않아야 한다.
3. 목록의 마감일·우선순위·사용자 값을 눌러 편집하고 저장/취소한다.
   숫자 0과 체크 false를 저장한다. 두 탭에서 같은 작업을 바꿔 충돌을 낸다.
   입력 보존→최신 작업 불러오기→별도 저장을 확인한다.
4. `+ 보기`로 이름을 붙여 저장하고 목록/보드/캘린더/집계와 필터·열 설정을
   복원한다. 탭의 `…`에서 이름 변경·복제·개인 기본을 바꾼다. 필드/필터를
   바꾸면 미저장 표시와 ‘현재 보기 업데이트’를 확인한다.
5. 보기 삭제를 취소한 뒤 다시 삭제한다. 작업과 현재 화면이 유지돼야 한다.
   모바일은 가로로 저장 보기 탭을 탐색하고 네 보기 직접 전환과 보드 좌우
   스크롤·필드 편집을 함께 확인한다.

## 추가 QA · 직접 편집·설정·프로젝트 메뉴

2026-11-03 운영 반영. 기존 샘플을 초기화하거나 가짜 실행 결과를 추가하지 않았다.

1. 개요의 프로젝트명을 눌러 수정하고 Enter 저장/새로고침한다. GNB·목록·전체
   작업의 소속명만 바뀌고 프로젝트 선택·목표·작업 ID는 유지돼야 한다.
2. 프로젝트 항목 또는 개요의 `…`에서 이름 수정/ZIP 내려받기를 확인한다.
   GNB에는 프로젝트 ZIP·테마 선택창이 없어야 한다. 모바일 프로젝트 목록에서도
   같은 항목 메뉴를 연다.
3. 작업 목록/보드 제목을 눌러 입력하고 Enter 저장/Esc 취소한다. 보드 제목을
   끄는 동작은 기존 카드 이동이며 클릭과 구별한다. 목록의 진행 상태도 값을
   선택해 바꾼다. 개인 완료 체크와 구현 완료 gate를 함께 확인한다.
4. 작업 상세의 제목·본문·상태·유형·날짜·예상 시간·다음 행동·사용자 속성을
   각각 눌러 바꾼다. 본문 링크 클릭/텍스트 선택이 편집 시작으로 바뀌면 안 된다.
   Markdown은 Ctrl/⌘+Enter 또는 저장으로 확정한다.
5. 두 탭에서 동시 수정해 409를 만들고 입력 보존→최신 revision 명시 병합→
   별도 저장을 확인한다. 다른 속성의 최신 값이 보존돼야 한다. 본문 초안은
   새로고침/다른 메뉴 재방문 뒤 같은 본문 자리에서 계속 작성한다.
6. 유형 변경은 개인/구현의 완료 조건 차이를 확인한 뒤 명시 저장한다.
   구현으로 바꾼 뒤 테스트 필수가 켜지고, 근거 없는 완료나 완료한 개인 작업의
   안전하지 않은 구현 전환은 거부돼야 한다. 필요하면 작업을 재개해 전환한다.
7. GNB·사이드바·더보기의 설정·환경설정을 열어 UI 모드/색상 테마를 바꾼다.
   재방문/새로고침 후 같은 브라우저에서 유지되는지 본다. 선택한 프로젝트와
   좁은 GNB의 단일 헤더, 작업 입력/검색의 좌우 간격도 확인한다.

## 실제 생성·검증 범위

`scripts/seed-task-qa.py --owner pydemia`를 운영 앱 환경에서 실행했다.
cohort는 `[qa-seed:2026-11-02-task-workspace-v2]`다. 이름 충돌 시 저장을
거부하며 같은 cohort는 기존 자료를 재사용한다. 한 트랜잭션으로 생성하고
기존 목록 뒤에 추가한다. 실제 재실행은 `created=false`, 태스크 24개였다.

운영 DB/앱에서 QA 건수, 오늘의 지난 계획 포함, 완료 gate 409, 이동 이력
1건, 개인 기본 보기 3개와 정적 자산을 확인했다. 당시 개인 작업공간의 열린
작업은 23개(기존 1+QA 22), 오늘 8·Inbox 2·예정 5개였다. QA로 달라질 수 있다.

공개 HTTPS의 미인증 API 401·로그인 200·Microsoft 시작 302를 확인했다.
브라우저 제어 도구의 `failed to write kernel assets` 오류로 배포 후 인증된
UI 조작은 재검증하지 못했다. 로컬 UI 검사와 운영 UI·물리 기기 결과를 구별한다.
