## 사용자의 과업으로 재구성

| 사용자 과업 | 진입·기본 흐름 | 복잡도 상승 시 | 검증할 결과 |
|---|---|---|---|
| 지금 할 일 수집 | 작업 → 간편 → 오늘/Inbox/예정 → 제목 한 줄 추가 | 정교 보기에서 일정·GTD·ABC·근거 편집 | Inbox는 날짜 없이, 오늘은 오늘, 예정은 내일 기본값. 개인 작업은 즉시 완료 가능 |
| 프로젝트 작업 운영 | 정교 목록의 검색·상태·GTD/ABC 선택 | 같은 항목을 보드·캘린더·집계에서 확인, 보드에서 상태 변경 | ID·revision 하나를 재사용. 구현 작업의 완료 gate는 상세 편집으로 안내 |
| 아이디어 요건화 | 기획 → 아이디어 검색/선택 → 본문·근거 확인 → 스킬 작업 | 생성 후보의 요구·설계·작업·테스트를 선택 적용 | 기존 기능과 관계·revision을 따라갈 수 있음 |
| 문서·테스트 검토 | 종류 탭 → 검색된 항목 선택 → 본문/편집/관계/실행 탭 | 충돌 비교·과거 revision 복원·테스트 결과 | 초안 보존, 서버 revision 명시, Note 임시 범위 표시 |
| 스킬 제안 적용 | 새 실행의 대상·요청 → 스킬/근거 → 실행 이력 검색 | 결과·원본·고정 bundle 비교 후 후보별 적용 | 검토 전에는 원본 변경 없음. 선택하지 않은 문서 결과는 적용하지 않음 |
| 변경 영향 판단 | 추적의 전체/재검토/연결 없음 필터 → 관계 검토 | 기준선 revision과 현재 revision 대조 | 영향 판정 사유와 현재 근거를 구분 |

## 화면 구조와 공통 UI 계약

1. 앱 전체에 공통 `AppShell`·`SideNav`·`NativeSelect`를 사용한다. 현재
   프로젝트·메뉴·로그인 상태를 항상 찾을 수 있고, 좁은 화면에서는 메뉴를
   가로 탐색으로 바꾼다.
2. 기획·문서·테스트·스킬 실행은 공통 **목록 → 상세** 흐름으로 구성한다.
   왼쪽은 `Card`·`SearchInput`·`SideNavLink`의 선택 목록, 오른쪽은
   `Card` 상세다. 항목 종류와 상세 행동은 `Tabs`, 필드·상태는 `Field`·
   `NativeSelect`·`Checkbox`·`DataList`를 쓴다. 선택과 검색은 URL로
   복원하고, 새 항목·복원·영향 판정은 `Dialog`로 집중한다.
3. 작업 화면의 **간편/정교**는 데이터 유형이나 색상 테마가 아니라 보기
   밀도다. 간편은 오늘·Inbox·예정과 한 줄 입력, 개인 완료를 먼저 보여
   주고 GTD/ABC 옵션은 펼쳐서 사용한다. 정교는 필터·보드·캘린더·집계와
   상태 조작·상세 근거를 보여 준다. `Tabs`와 `SegmentedControl`로 전환하며
   같은 작업과 revision을 유지한다.
4. 추적 화면은 `SegmentedControl` 필터, `Table`, `Accordion` 기준선으로
   검토 대상을 좁힌다. 요구사항·문서·작업·테스트의 연결과 결측 상태를
   색에만 의존하지 않고 텍스트로 표시한다.
5. 개요에는 `MetricCard`와 다음 행동/최근 편집 `Card`를 두고 각각 실제
   업무 항목으로 이동한다. 집계는 `BarList`의 현재 스냅샷이며 추세로
   표시하지 않는다.

개별 `pyd-<component>` source, revision, SHA-256과 의존성은
[편입 기록](ui-component-integration.md)에 적는다. Projects는 경로·API·
업무 제약과 데이터 변환만 소유한다. 컴포넌트의 의미·키보드·focus·
상태 표현을 별도 모양의 로컬 복제품으로 다시 만들지 않는다.

## 구현 순서와 수용 기준

| 단계 | 구현 | 수용 기준 |
|---|---|---|
| 1 | 공통 외곽·상태·모달·폼·토큰 정리 | 모든 화면에서 같은 현재 위치, light/dark·UI 모드, 키보드 포커스 |
| 2 | 간편 수집·정교 작업 운영 | 제목만으로 추가, Inbox/오늘/예정 자동 기본값, 같은 작업의 보기 전환, 보드 상태 변경, 완료 gate |
| 3 | 기획·문서·테스트·SkillRun의 목록/상세 | 검색·종류/편집 탭·선택·초안/충돌/결과 적용이 화면 이동 후에도 이해 가능 |
| 4 | 추적·기준선과 개요 | 재검토/연결 없음 필터, 관계/기준선, 현재 스냅샷과 실제 링크 |
| 5 | 품질·운영 | TypeScript/Vitest, PostgreSQL 계약, 빌드, 데스크톱/모바일 운영 브라우저, favicon·테마·선택 상태 확인 |

AC-35: 1~4단계의 모든 주요 화면에 실제 pydemia UI source 컴포넌트가
레이아웃과 업무 조작에 적용된다. 버튼·입력만 교체한 상태는 불합격이다.

AC-36: 간편 모드에서는 제목 입력→저장→완료가 기본 경로이며 추가 필드는
펼침/정교 보기에 둔다. Inbox·오늘·예정의 자동 날짜와 동일 ID를 확인한다.

AC-37: 정교 목록·보드·캘린더·집계는 같은 필터와 항목을 사용한다. 보드의
개인 상태 변경은 revision 검사로 저장하고, 구현 완료에는 서버 완료 gate를
우회하지 않는다.

AC-38: 아이디어/문서/테스트/스킬 실행/추적에서 검색·선택·탭·검토·오류·
빈 상태가 일관된 구조로 작동한다. 복원·변경 영향 Dialog는 Escape와
포커스 복귀를 지원한다.

AC-39: Basic light/dark, 형태가 다른 출시 UI 모드, 좁은 화면과 실제 로그인
브라우저에서 핵심 경로를 확인하고, mock·로컬·운영 근거를 구분한다.

전 프로젝트 Today, 고급 필터 저장, 드래그 보드, GitHub 양방향 동기화와
시계열/실측 그래프는 각 데이터·권한 계약 이후의 확장이다. 해당 기능을
현재 화면이 제공하는 것처럼 표시하지 않는다.
