# UI·UX 기획

상태: 추천 구조 A / 검토용 revision A-02 · 2026-10-21

## 정보 구조

전역에는 프로젝트 목록·아이디어 보관함·독립 문서 작업·스킬 목록·검색·개인 설정을 둔다. 기본 작업창은 사용자 메모/대화·현재 스킬 실행과 근거·산출물 미리보기로 구성한다. 프로젝트 내부에서는 왼쪽에 업무 영역, 상단에 현재 범위·기준선, 본문에 목록 또는 문서, 오른쪽에 선택 대상의 근거·영향·검토 정보를 둔다. 화면 폭이 좁으면 근거 영역을 별도 탭이나 본문 뒤로 이동한다.

```text
작업공간
├─ 프로젝트 목록
├─ 아이디어 보관함 / 요건화 작업창
├─ 독립 문서 작업 / 스킬·실행 이력
└─ 프로젝트
   ├─ 개요              다음 행동·진척·차단 사유
   ├─ 기획              아이디어·요구사항·기능 기획·UI 기획
   ├─ 설계              System / Infra / Application / Interface
   ├─ 구현 계획·작업     마일스톤·WBS·의존성·보드/목록
   ├─ 테스트            케이스·실행·결함·근거
   ├─ 산출물            단계와 무관한 문서·파일 통합 목록
   ├─ 추적·변경          요구사항별 연결표·영향 검토·결정
   └─ 프로젝트 설정      프로필·필수 문서·연동·권한
```

기획·설계는 산출물의 단계별 보기다. 산출물 메뉴에서도 같은 객체를 열며 별도 복제하지 않는다. URL에는 프로젝트·범위·선택 객체·탭·필터를 반영한다. 목록에서 상세로 갔다 돌아오면 필터·선택·스크롤을 복구한다.

## 문서 편집 흐름

문서 제목 아래 유형·revision·검토 상태를 표시한다. 본문은 읽기 좋은 연속 문서로 구성하고 섹션별 카드로 나누지 않는다. 우측에는 문서 목차, 참조 요구사항, 관련 작업·테스트, 미해결 질문을 둔다. 입력·본문·검토 조작의 적용 범위를 구분한다.

초안 저장은 내용 보존, 검토 요청은 해당 revision 제출, 확정은 합의된 revision 고정이다. 변경은 서버의 revision을 비교한 후 저장한다. 충돌하면 내 초안과 서버 버전을 나란히 보여 주고 덮어쓰기 전에 병합한다. 네트워크 실패 시 화면의 입력을 유지하고 재시도 가능하게 한다.

확정본을 읽을 때는 확정 이력과 현재 초안 링크를 함께 표시한다. “이 버전 복원”은 새 초안을 만든다. 외부 문서는 원본 링크·업로드 버전·마지막 확인 시점을 보여 주며 링크가 있다는 이유로 최신 또는 확정으로 표시하지 않는다.

## AI 제안 흐름

문서 작업의 기본 동작은 “스킬로 작성/수정/검수”다. 사용자가 자연어로 요청하거나 행동을 선택하면 사용 스킬·고정 revision·입력 근거·보존 범위를 보여 준다. 작업은 문서·도구 결과·검수 기록을 산출한다. 큰 의미 변경은 별도 제안으로 비교한다. 시안의 “스킬 실행”에서는 고정 결과로 이 흐름을 보여 준다. 사용자가 실행 범위를 확인한 뒤 생성한다. 결과는 본문을 즉시 바꾸지 않고 별도 제안 영역에 표시한다. 출처·가정·미정 질문을 본문과 구분한다.

취소하면 저장된 문서와 편집 중인 초안이 그대로 남는다. 선택 채택은 편집 초안에 반영되고 사용자가 저장한 다음 문서 revision이 된다. AI 제안에 승인·확정 버튼은 없다. 생성 중 문서를 수정해도 입력을 지우지 않으며 기준 revision이 달라지면 적용 전에 충돌을 안내한다.

## 시각적 구성

중립적인 밝은 바탕과 한 가지 강조색을 기본 제안으로 사용한다. 목록·표는 정렬과 행 간격, 본문은 제목·단락, 선택 상태는 면, 편집 입력은 명확한 경계로 구분한다. 우측 근거 영역은 본문과 다른 조작 범위이므로 하나의 구분선을 유지한다. 떠 있는 대화상자에만 elevation을 사용한다.

같은 수준의 문서와 작업에는 같은 행 표현을 반복한다. 오류·선택·재검토처럼 의미가 달라지는 경우에만 표현을 바꾼다. 새 버튼과 입력은 `corner-shape: squircle` 지원 시 적용하고 미지원 브라우저에서는 작은 rounded corner로 대체한다. CSS radius만으로 실제 squircle을 구현했다고 간주하지 않는다.

## 공통 UI 시스템과 테마 적용 결정

구현 화면의 기본 컴포넌트·디자인 토큰은 [pydemia UI](https://ui.pydemia.ai/)의 공개 registry 소스를 사용한다. `@pydemia/ui`는 공개 npm 설치 대상으로 가정하지 않으며, 선택한 원본을 Projects 소스에 고정하고 revision·의존성·고지를 기록한다. A-02 HTML 시안은 당시 검토 자료이고 현재 제품의 컴포넌트 출처를 나타내지 않는다.

| 화면 역할 | 공통 소스 | Projects 적용 |
|---|---|---|
| 주요 행동·입력 | `pyd-button`, `pyd-input`, `pyd-textarea`, `pyd-label` | 로그인·프로젝트 생성·공통 필드와 대화상자 행동 |
| 정보·상태 | `pyd-page-header`, `pyd-badge`, `pyd-alert`, `pyd-empty` | 목록 제목, 업무 상태, 오류와 빈 상태 |
| 외형 설정 | `pyd-tokens`, `pyd-design-modes`, `ThemeScope` | 화면 전체 색·타이포·표면과 portal 범위 |

UI 모드는 registry가 `released`로 표시한 21개만 선택한다. Basic을 초기값으로 하고 light/dark는 독립된 설정으로 제공한다. Dark UI·Cyberpunk UI·Terminal UI처럼 dark 전용인 모드에서는 light를 선택할 수 없게 한다. 선택은 브라우저에 보존하되 프로젝트 업무 데이터·문서 내용·공유 URL을 바꾸지 않는다. 기존 레이아웃 CSS는 업무 구조에 한정하고 색·표면·경계는 공통 semantic token에 연결한다. 긴 한국어와 좁은 화면, 키보드 포커스, 상태의 텍스트 식별을 각 테마에서 확인한다.

웹 배포에는 favicon을 수용 조건으로 포함한다. 기존 승인 pydemia 엠블럼의 기하를 유지한 작은 SVG 파생형을 사용하고, light/dark 브라우저 탭에서도 식별되는지 확인한다. 기획 단계는 자산·`rel=icon` 경로·빌드·실제 HTTPS 응답·탭 표시 검사를 인계한다. 로고·엠블럼 자체의 새 설계는 이 화면 개편 범위가 아니다.

## 작업공간 확장: 간편/정교 보기

[6개 제품 공식 자료의 비교와 채택 범위](12-task-workspace-benchmark.md)를
기준으로 기존 `구현 작업` 화면을 개인 할 일에도 사용할 수 있게 한다.
`간편 · To-do`/`정교 · 프로젝트`는 프로젝트 생성 프로필이나 21개 시각
UI 모드와 별개인 보기 밀도다. 전환해도 저장된 작업·revision·관계는 같다.

간편 보기의 첫 화면은 오늘이다. 상단 한 줄 입력은 개인 할 일을 오늘
실행 예정으로 저장한다. 오늘·Inbox·예정은 작업을 복제하지 않는 스마트
목록이다. 완료 단추는 개인 할 일만 즉시 처리한다. 구현 작업은 상세로
이동해 기존 완료 근거를 확인한다. 정교 보기는 목록의 검색·상태·GTD/ABC
정렬, 상태 보드, 월간 실행/마감 캘린더, 현재 스냅샷 집계를 제공한다.
정교 보기의 상세 편집에는 목표·가치, ABC, GTD 맥락·예상 시간·에너지,
GitHub Issue URL, 구현 작업의 수용 조건과 테스트 근거를 배치한다.

주요 관계는 `보기 밀도 → 작업 보기 → 필터/정렬 → 작업 선택·편집`이다.
상단 두 축의 선택을 분리해 사용자가 light/dark 또는 디자인 모드를 바꿀 때
작업 보기 설정이 바뀌지 않게 한다. 보드 열은 같은 상태의 항목 묶음,
캘린더 셀은 실행 예정·마감의 시간 위치, 그래프 막대는 현재 건수의 비교다.
긴 제목은 줄바꿈하고 모바일에서 보드는 가로 스크롤, 캘린더는 명시된
가로 영역으로 탐색한다. 빈 결과, 저장 실패, 409 revision 충돌과
GitHub URL 오류는 입력을 보존한 상태로 표시한다.

## A-02 시안 범위

[HTML 시안](prototype/index.html)은 개요·아이디어 요건화·산출물/문서·구현 작업·테스트·추적 화면을 연결한다. 스킬 실행 UI는 사용 스킬·근거·산출물 제안을 함께 표시한다. 문서 선택·검색, 편집 저장·취소, 예시 AI 제안의 선택 채택·취소, 테스트 결과 기록, 요구사항 변경 영향 확인을 시연할 수 있다. 새로고침하면 예시 데이터로 돌아간다. 실제 서비스의 저장·권한·AI·동기화 품질을 검증하는 구현은 아니다.

화면 수치와 내용은 모두 예시다. 백엔드 오류·동시 편집·프로젝트 생성·실제 업로드·외부 반출은 명세만 정의했으며 A-02의 동작 범위에 들어 있지 않다.
