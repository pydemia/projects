APP-REQ-059~061: 다른 계정의 Entra 승인 후 500을 조사·수정하고, 신뢰 조직

인증 멀티테넌시 구현과 프로젝트 공유 구현, 합성 토큰 검사와 실제 계정 로그인을 구분한다.

같은 날 후속 사용자 결정으로 로그인은 `pydemia.ai` 조직 계정으로 유지하고,
업무 권한은 프로젝트별로 부여한다. 한 사용자의 역할은 프로젝트마다 다를 수
있고, 권한 있는 프로젝트만 목록·검색·전체 작업·집계에 나타난다. 프로젝트의
`멤버·권한`에서 역할과 허용 동작을 관리한다. Workspace 역할을 일괄 상속하는
이전 제안은 이 결정으로 대체한다. APP-REQ-061 / AC-135~137은 목록 비노출,
프로젝트별 역할·동작, 권한 변경·철회의 현재 적용을 추적한다.

활성 권한은 18개이며 오너·에디터·뷰어와 프로젝트별 사용자 지정 역할로
서버가 요청마다 현재 권한을 강제한다. 보관·복원은 오너 전용이고 작업/프로젝트
삭제 코드는 예약 상태로 실제 기능·활성 권한·설정 체크 항목에 포함하지 않는다.
공유 필드는 프로젝트에, 개인 보기·목록 순서는 계정에 귀속한다. SkillRun·ZIP·
이동은 실제 요청자와 원본/적용 항목의 현재 프로젝트 권한을 검사한다.

초대·소유권 수락은 최신 revision의 미리보기 뒤 명시적으로 확정한다. 수락 token은
URL fragment에 두고 로그인 이동 전 같은 탭의 `sessionStorage`에 최대 15분
checkpoint하며 인증 redirect URL에는 넣지 않는다. 인증 복귀만으로 자동 수락하지
않는다. UI는 15초 주기와 화면 복귀 시 권한을 갱신하고 서버는 즉시 현재 권한을
적용한다. 격리 PostgreSQL·실제 HTTP·Edge desktop/모바일 폭의 여러 계정 검사는
완료했다. 운영 `986e0a1af12655bb` 반영 후 schema `0012`·현재 멤버십·기존 자료
fingerprint 보존과 공개 Edge 4개 checkpoint를 확인했다. 실제 Microsoft 다른
계정의 승인 후 로그인은 미검증이다. 운영 전환 결과는
[배포 기록](../implementation/deployment.md), 로컬 검사의 세부 범위는
[권한 구현 goal](../implementation/project-access-goal.md)과
[검증 기록](../implementation/verification.md)을 따른다.
